# КАЮК SLICE — техническое задание на игровые ассеты

Версия: 1.0  
Статус: спецификация для производства графики  
Цель: подготовить полный, согласованный набор игровых изображений для перехода на Phaser 3 без изменения существующей серверной экономики.

## 1. Общие художественные правила

- Направление: premium arcade / football night.
- Игровая сцена: вертикальная, ночной стадион, глубокий navy, холодные голубые акценты.
- Предметы: объёмные, стилизованный реализм уровня качественной мобильной аркады; не плоские иконки, не emoji, не текст на цветном круге.
- Свет: единый ключевой свет сверху-слева, мягкий холодный контровой свет справа, читаемый силуэт.
- Камера: предмет показан целиком, без обрезания, лёгкий 3/4 ракурс, если он не мешает узнаваемости.
- Фон каждого предмета: прозрачный alpha, без теней, запечённых на фон. Контактную тень и glow создаёт Phaser.
- Запас прозрачных полей: минимум 12% от габаритов холста со всех сторон.
- Не добавлять надписи, которых нет в утверждённом дизайне. Лейблы должны быть чёткими при игровом размере.
- Не менять пропорции предмета между целым видом и половинками.

## 2. Форматы и размеры

### Исходники
- Мастер-изображение каждого предмета: PNG RGBA, 1024×1024 px.
- Половинки: отдельные PNG RGBA, 1024×1024 px каждая, с одинаковым масштабом и точкой сборки.
- Векторные логотипы/эмблемы, если доступны: SVG; растр для игры — PNG.
- Все исходники хранятся отдельно от оптимизированной сборки.

### Игровая сборка
- Основной спрайт: PNG RGBA 512×512 px (или 512×768 для высоких бутылок).
- Половинки: PNG RGBA, тот же холст и тот же pivot, что у целого предмета.
- Допустим WebP lossless только для тестовой оптимизации; alpha и края обязательно проверить на тёмном фоне.
- Атлас текстур: упаковка после утверждения всех отдельных спрайтов. Не объединять в один гигантский атлас до проверки на iPhone.
- Целевой размер одного игрового спрайта: желательно до 250 KB; бутылки с мелкими деталями — до 400 KB.
- Для анимаций использовать texture atlas + JSON Phaser или отдельные кадры, если так надёжнее для сборки.

## 3. Соглашение об именах файлов

Папки:
- `public/assets/slice/items/` — предметы.
- `public/assets/slice/fx/` — эффекты.
- `public/assets/slice/ui/` — интерфейс.
- `public/assets/slice/audio/` — звуки.

Шаблон имени предмета:
- `<id>_whole.png` — целый предмет.
- `<id>_half_a.png` — первая половинка.
- `<id>_half_b.png` — вторая половинка.
- `<id>_preview.png` — опциональная миниатюра для каталога/правил.

ID всегда латиницей, lowercase, без пробелов. Названия в интерфейсе задаются отдельно в коде.

Разрез клубной бутылки:
- Две стеклянные половинки с прозрачными краями.
- На срезе — видимая толщина стекла и светлый блик.
- Этикетка физически разделяется по линии разреза; не дублировать целую эмблему на обеих половинках.
- После разреза — несколько мелких стеклянных осколков как отдельный particle effect, не перегружать экран.

Примечание по эмблемам: если используются официальные логотипы, брать качественные исходники из разрешённых источников или предоставленные пользователем. Не перерисовывать эмблему приблизительно так, чтобы она выглядела как ошибочный официальный знак. При отсутствии исходника использовать явно стилизованный оригинальный щит с названием клуба.

Общие эффекты:

## 7. Состояния и анимации каждого предмета

Обычные фрукты и бутылки:
1. Spawn — вход снизу с небольшим разбросом.
2. Flight — вращение и движение по дуге.
3. Slice — короткая вспышка в точке касания.
4. Split — две половинки расходятся с разными скоростями и вращением.
5. Fall — половинки падают за пределы сцены.
6. Despawn — удаление объекта и освобождение памяти.

Дополнительные состояния:
- Бонусная бутылка: короткий glow при появлении и отдельный бонусный burst при разрезании.
- Абсент: опасный зелёный сигнал, затем эффект столкновения/штрафа.
- Бомба: анимация фитиля, мигание перед взрывом, взрыв, частицы и короткий screen shake.

## 8. Правила технической приёмки графики

Ассет считается готовым только если:
- У него есть прозрачный фон без белого/чёрного ореола.
- Нет обрезанных краёв, фитиля, листьев, крышек или выступающих деталей.
- Предмет узнаваем при размере около 90–140 CSS px на экране iPhone.
- Детали этикетки не превращаются в нечитаемое пятно.
- Целая версия и половинки совпадают по масштабу, ракурсу и освещению.
- Половинки при визуальной сборке точно складываются в исходный предмет.
- На тёмном и светлом тестовом фоне нет грязных контуров.
- Атлас не содержит пересечений, обрезанных кадров и неверных pivot.
- Проверены загрузка, отрисовка и производительность на реальном iPhone.

## 10. Важные ограничения интеграции

- На этом этапе не менять `api/slice/start.js`, `api/slice/finish.js`, `api/slice/leaderboard.js`, Supabase RPC и таблицы.
- Не менять курс 1:1, тип транзакции `slice_reward`, механизм idempotency и общий баланс.
- Смена Canvas на Phaser 3 должна быть отдельным этапом и отдельным PR.
- Сначала утвердить и проверить ассеты; затем подключать их через единый asset manifest.
- Не загружать непроверенные тяжёлые атласы прямо в production.
